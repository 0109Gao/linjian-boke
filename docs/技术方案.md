# 林间博客（Vue3 + Spring Boot + MySQL）技术方案

> 面向简历/就业导向的技术栈重构版本。原项目为「原生 JS + WorkBuddy 云数据库」，本方案将其改写为主流的 **前后端分离** 架构，用于体现完整的前后端工程能力。

---

## 一、项目定位

一个对标 CSDN 的多人博客系统，支持会员注册登录、文章发布与审核、评论盖楼、点赞收藏、分类标签、全文搜索、RSS 订阅、管理员后台。

**核心卖点（简历可写）**：
1. 前后端分离架构，RESTful API 设计规范
2. Spring Security + JWT 无状态认证，三级权限（访客 / 会员 / 站长）
3. 会员发文章需审核的完整工作流
4. 数据库级权限兜底 + 业务层校验双保险
5. 点赞收藏的幂等设计（唯一约束 + 乐观更新）

---

## 二、技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite + Vue Router + Pinia | 组件化 SPA |
| UI 组件库 | Element Plus | 后台 + 表单 |
| HTTP | Axios | 封装请求拦截器（自动带 token） |
| 后端 | Spring Boot 3.x | REST API |

| ORM | MyBatis-Plus | 简化 CRUD |

## 四、数据库设计（MySQL 建表）

### 4.1 表清单

| 表名 | 说明 | 关键字段 |
|---|---|---|
| `user` | 用户（含角色） | id, username, password(加密), nickname, avatar, role, status |
| `category` | 文章分类 | id, name, sort |
| `tag` | 标签 | id, name |
| `post` | 文章 | id, user_id, title, slug, content, summary, cover, category_id, status, pinned, views, like_count, created_at, updated_at |
| `post_tag` | 文章-标签关联 | post_id, tag_id |
| `comment` | 评论（支持盖楼） | id, post_id, user_id, parent_id, content, status, created_at |
| `like` | 点赞 | id, user_id, target_type, target_id, created_at |
| `favorite` | 收藏 | id, user_id, post_id, created_at |
| `subscription` | 订阅 | id, email, created_at |

### 4.2 关键设计说明

1. **`user.role`**：`ADMIN`（站长）/ `MEMBER`（会员）。第一个注册的账号自动成为 ADMIN。
2. **`post.status`**：`PUBLISHED` / `PENDING`（待审核）/ `DRAFT`。会员发文章默认 `PENDING`，站长可直接 `PUBLISHED`。
3. **`comment.status`**：`APPROVED` / `PENDING` / `SPAM`。由 `comment_moderation` 站点开关控制是否即时可见。
4. **`like` 幂等**：`UNIQUE KEY uk_like (user_id, target_type, target_id)`，防重复点赞。
5. **盖楼**：`comment.parent_id` 指向父评论，`NULL` 表示顶级评论；查询时在内存中组装树（避免递归 SQL 性能问题）。
6. **`post.slug`**：URL 友好标识，唯一索引，用于文章详情页直链（SEO）。

见 `sql/schema.sql`（随代码骨架一起交付）。

## 五、REST API 设计

统一前缀 `/api`，统一返回格式：

```json
{ "code": 0, "message": "success", "data": {} }
```

| 模块 | 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|---|
| 认证 | POST | `/api/auth/register` | 公开 | 注册（首个账号=ADMIN） |
| 认证 | POST | `/api/auth/login` | 公开 | 登录，返回 JWT |
| 认证 | GET | `/api/auth/me` | 登录 | 当前用户信息 |
| 文章 | GET | `/api/posts` | 公开 | 文章列表（分页/筛选） |
| 文章 | GET | `/api/posts/{id}` | 公开 | 文章详情 |
| 文章 | POST | `/api/posts` | 会员 | 发布（会员自动 PENDING） |
| 文章 | PUT | `/api/posts/{id}` | 作者/站长 | 编辑 |
| 文章 | DELETE | `/api/posts/{id}` | 作者/站长 | 删除 |
| 审核 | PUT | `/api/admin/posts/{id}/audit` | 站长 | 通过/驳回 |
| 评论 | GET | `/api/posts/{id}/comments` | 公开 | 评论列表（树形） |
| 评论 | POST | `/api/posts/{id}/comments` | 会员 | 发表评论 |
| 评论 | POST | `/api/comments/{id}/reply` | 会员 | 盖楼回复 |
| 点赞 | POST | `/api/likes` | 会员 | 点赞/取消（幂等） |
| 收藏 | POST | `/api/favorites` | 会员 | 收藏/取消 |
| 分类 | GET | `/api/categories` | 公开 | 分类列表 |
| 标签 | GET | `/api/tags` | 公开 | 标签列表 |
| 搜索 | GET | `/api/search?q=` | 公开 | 全文搜索 |
| 订阅 | POST | `/api/subscribe` | 公开 | RSS 订阅 |

## 六、权限模型（三级）

| 角色 | 浏览 | 评论 | 点赞收藏 | 发文章 | 审核 | 后台 |
|---|---|---|---|---|---|---|
| 访客 | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 会员 | ✅ | ✅ | ✅ | ✅（需审核） | ❌ | ❌ |
| 站长 | ✅ | ✅ | ✅ | ✅（直接发布） | ✅ | ✅ |

**权限实现**：
- 认证：Spring Security 过滤器解析 JWT，注入 `SecurityContext`。
- 授权：`@PreAuthorize` 注解 + 自定义 `@RequireRole` 注解。
- 资源归属：Service 层校验「操作者是否为资源所有者或站长」。

## 七、关键设计决策

1. **为什么选 MyBatis-Plus 而非 JPA**：国内企业主流，SQL 可控，面试熟悉度高，简历认可度高。
2. **为什么用 JWT 而非 Session**：前后端分离 + 无状态，便于横向扩展。
3. **为什么评论树在内存组装**：避免递归 SQL 性能问题，评论量级可控时最高效。
4. **审核工作流**：会员发文章 → `PENDING` → 站长在后台审核 → `PUBLISHED`。前端会员列表只显示自己的文章（含待审核），公开列表只显示 `PUBLISHED`。
5. **点赞幂等**：数据库唯一约束兜底 + 前端乐观更新（点立即 +1，失败回滚）。
